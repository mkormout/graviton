<objective>
Add object pooling for high-frequency spawned entities (bullets, death
explosions, bullet-impact FX, debris) to eliminate per-frame `PackedScene.instantiate()`
allocations. At Wave 20 with minigun spooled, the game currently instantiates
dozens of `RigidBody2D`/`CPUParticles2D` scenes per second; this replaces that
with pre-allocated pools that reuse instances.

Purpose: Next performance step after 260423-w6g (Timer elimination). Each
`instantiate()` on a physics-heavy scene (bullets have RigidBody2D +
CollisionShape2D + Line2D + death sub-scenes) costs ~0.5–2ms at wave peaks
and produces GC/arena pressure. Pooling converts those spikes into a fixed
cost at scene init.

Output: Generic ScenePool + PoolManager autoload, pooled bullets/FX/explosions
across all weapons and enemies, with behavior preserved 1:1.
</objective>

<architecture_decision>
**Autoload `PoolManager` + generic `ScenePool` instances keyed by PackedScene.**

Why this over alternatives:
- **Per-spawner pools** rejected: each weapon holds its own bullet pool means bounced laser children can't find the pool (they're recursive), and cross-ship sharing is impossible.
- **Per-scene (world.tscn) pool node** rejected: pools must survive `_restart_game()` which currently just frees children; autoload is the cleanest survival path (same pattern as MusicManager/ScoreManager already used in this codebase — see `project.godot` autoloads).
- **Autoload PoolManager** selected: single global keyed by `PackedScene`, lazy pool creation on first `acquire`, `clear_all_in_tree()` hook for restart.

Interface:
```gdscript
# Autoload
PoolManager.acquire(scene: PackedScene) -> Node       # returns fresh-or-reused, out-of-tree
PoolManager.release(node: Node) -> void               # reparents to pool, resets it
PoolManager.prewarm(scene: PackedScene, n: int)       # optional pre-allocate
PoolManager.clear_live()                              # release all in-flight instances (restart)
PoolManager.stats() -> Dictionary                     # { scene_path: {live, free, total} }
```

**Lifecycle idiom (Godot 4.2):** `remove_child()` on release + `add_child()` on acquire.
- Keeping nodes in-tree with `process_mode=DISABLED` + disabled CollisionShape2D was
  considered, but `contact_monitor`/`body_entered` signals remain wired on disabled
  RigidBody2D and caused subtle re-entrancy in a scratch test. Reparenting is the
  idiomatic Godot 4 pool pattern and matches what `MountPoint.plug()` already does.
- Pool holds released nodes as children of the PoolManager autoload node (off-tree
  from gameplay physics).
- `_pool_reset()` contract called on acquire: clear `linear_velocity`, `angular_velocity`,
  `rotation`, re-enable `contact_monitor`, reset subclass state (`_life_left`,
  `_die_left`, `dying`, `health`, `bounce_count`, etc.).

**Exhaustion policy:** **grow dynamically** (allocate one more and log once per scene
at 2× initial size). Rationale: gameplay feel — a missing bullet feels broken;
pool sizes were tuned for worst-case, growth handles outliers without drops.

**Initial pool sizes** (prewarmed by PoolManager in `_ready`):
- minigun-bullet: 60 (worst case ≈ max spool rate × life)
- gausscannon-bullet: 8
- rpg-bullet: 6
- laser-bullet: 40 (3 weapons × max_bounces 3 × branch factor 2)
- gravitygun-ammo: 4
- enemy bullets (flanker/beeliner/sniper/swarmer): 24 each
- bullet-impact FX: 40
- laser-bounce-flash FX: 30
- death explosion scenes (one per bullet type): 20 each

Sizes are constants in `pool-manager.gd` — tune in one place.
</architecture_decision>

<reset_contract>
**Every pooled scene MUST implement `_pool_reset()` (or be a plain particle
that the pool resets via a generic path).** The ScenePool calls `_pool_reset()`
on acquire if the node has the method, otherwise applies the default reset:

Default reset (applied by ScenePool when `_pool_reset` is absent):
- If node is `RigidBody2D`: `linear_velocity = Vector2.ZERO`,
  `angular_velocity = 0.0`, `sleeping = false`, clear collision exceptions.
- If node is `CharacterBody2D`: `velocity = Vector2.ZERO`.
- `rotation = 0.0`, `scale = Vector2.ONE`.
- `visible = true`, `process_mode = PROCESS_MODE_INHERIT`.
- If node is `CPUParticles2D`: `emitting = false` then `restart()` lined up
  for next frame by the consumer (FX consumers call `restart()` after acquire).

Subclass `_pool_reset()` implementations must:
- Reset any `_life_left`, `_die_left`, `_fire_left`, timers, etc. to inactive.
- Reset `dying = false`, `health = max_health` (Body subclasses).
- Clear cached state: `bounce_count = 0`, `_target = null`, `shooter = null`,
  `spawn_parent = null` (caller re-assigns after acquire).
- Remove collision exceptions added in `_ready` (laser).

The equivalent `_ready` initialization MUST move into `_pool_reset()` so
a reused instance gets the same setup a fresh one would.
**Do not call `super._ready()` from `_pool_reset()`** — `_ready` still fires
on first-ever acquire only (because of add_child); subsequent reuses run
`_pool_reset` only.
</reset_contract>
